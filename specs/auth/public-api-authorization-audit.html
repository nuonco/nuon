Public API Authorization Audit

Every public-API route (port 8081) and what authorization allows access to it. Generated from the route inventory and the live middleware classifiers on ja/resource-grants-v2.

480 routes · 2026-08-09 · companion to resource-grant-denormalized-owners.html and resource-grants.html

How to read this.
  • Accounts holding an org role short-circuit on the org-wide permission check and can reach every route (subject to the method permission). The per-route rules below describe grant-scoped accounts — accounts whose access comes from resource grants.
  • The permission required is derived from the HTTP method: GET/HEAD → read, POST → create, PUT/PATCH → update, DELETE → delete. A grant must carry at least that permission on some link of the resource’s chain.
  • A resource’s chain is [install → app → org] (or the applicable suffix). A grant on any link authorizes the request — grants elevate, they never restrict.
  • Special case: POST .../components/:component_id/builds authorizes against the org’s component_builds object for org-wide accounts (runner role), in addition to the chain rules below.
