App Branch Run Flow

How an app-branch run triggers install updates, config versioning, and diff tracking

1. Trigger App Branch Run
HTTP POST User triggers a branch run (manual or git push). Creates AppBranchRun record (status=pending) and master workflow.
apps/service/trigger_app_branch_run.go
2. Master Workflow Orchestration
Steps executed in sequence:
• Fetch commit from VCS
• Fetch app config (parse nuon.toml)
• Build components (create OCI artifacts)
• For each install group: plan → deploy
apps/workflows/app_branch_run.go
3. Update Install Group
updateinstallgroup For each install group, resolves install IDs (static list or label selector), creates InstallGroupRun, then enqueues per-install workflows.
apps/signals/branches/updateinstallgroup/execute.go
FOR EACH INSTALL IN GROUP
3a. Create Install Config Update Workflow
activity Computes InstallConfigDiff (component checksums, sandbox/stack changes).
Creates InstallAppConfigVersion record (status=pending) with diff blob.
Creates per-install workflow and enqueues it.
apps/signals/branches/activities/create_install_config_update_workflow.go
↓
3b. Per-Install Workflow (app_branch_config_update)
Reads diff from InstallAppConfigVersion record.
Generates steps based on what changed:
• Stack reprovision (if stack changed)
• Sandbox reprovision (if sandbox changed)
• Deploy only changed + added components (skips removed and unchanged)
installs/workflows/v2/app_branch_config_update.go
↓
3c. Await Completion + Callback
Parent waits for all per-install workflows to complete via callbacks.
Updates InstallGroupRun status: "4/5 installs deployed (1 failed)"
4. Record App Config Versions
update-app-config For each successful install, enqueues the update-app-config signal with triggered_by: "app-branch"
apps/signals/branches/updateinstallgroup/execute.go → recordAppConfigVersions()
5. Update App Config Signal (single source of truth)
update-app-config This signal is the single source of truth for install config updates:

• Updates install.AppConfigID to new config
• For branch runs: finds existing InstallAppConfigVersion (created in 3a) and updates status to success + sets triggered_by metadata
• For sync runs: creates new InstallAppConfigVersion record with diff
• Enqueues appconfigupdated signal
installs/signals/updateappconfig/signal.go
6. App Config Updated Signal (reconciliation)
appconfigupdated Reconciles emitters to match new config:
• Action cron emitters (create/delete cron triggers)
• Component drift emitters (create/delete drift check schedules)
• Sandbox drift emitter
• Input migration
installs/signals/appconfigupdated/signal.go

Diff System Architecture

Two diff types serve different purposes

Diff Type Purpose Granularity Used By Storage
App Config Diff
pkg/config/diff.Diff		 Rich hierarchical diff of the full nuon.toml config.
Shows field-level changes in a tree structure.		 Entity-level counts:
+1 component, ~1 sandbox, -1 secret

Detail drill-down:
Per-field and per-file diffs within each entity 		• PR comment body
• Branch run detail UI (config diff card)
• Install version detail UI (planned) 		Computed on-demand via AppConfig.Diff(old)
or stored in InstallAppConfigVersion.Diff blob
Install Config Diff
app.InstallConfigDiff		 Component-level diff used to determine which workflow steps to run. Component lists:
Added[] Changed[] Removed[] Unchanged[]

Flags:
SandboxChanged, StackChanged 		• Per-install workflow step generation
• filterComponentsByDiff() in workflow 		Stored as blob in InstallAppConfigVersion.Diff

Section Counting (Entity-Level)

Every section shows entity-level counts, not field-level

Section Type What Counts as +1 Example
Components Grouped Each component is one entity Adding api and worker → +2
Actions Grouped Each action is one entity Adding deploy action → +1
Inputs Grouped Each input is one entity Adding region input → +1
Secrets Grouped Each secret is one entity Changing db_password format → ~1
Policies Grouped Each policy is one entity Removing approval-policy → -1
Sandbox Ungrouped Entire sandbox section is one entity Adding sandbox with 5 fields → +1 (not +5)
Runner Ungrouped Entire runner section is one entity Changing runner_type → ~1
Stack Ungrouped Entire stack section is one entity Adding stack config → +1
Permissions Ungrouped Entire permissions section is one entity Changing IAM roles → ~1
