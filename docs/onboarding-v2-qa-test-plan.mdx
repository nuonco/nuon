## Test Flow Per App

### Step 1: Organization (WelcomeNameOrgStep)

- [ ] Org name input renders with placeholder
- [ ] "Generate random name" button works
- [ ] Org creation shows spinner + progress messages
- [ ] Org card transitions to success state with green check
- [ ] Continue button appears after org is created
- [ ] If org already exists from prior run, shows success immediately

### Step 2: App Profile (AppProfileStep)

- [ ] Example apps catalog loads (16 apps visible)
- [ ] Apps are grouped by category (architecture, self-hosted)
- [ ] Selecting an app highlights the card
- [ ] Search/filter works across apps
- [ ] Continue advances to step 3
- [ ] Cloud provider is correctly set from the selected app (aws/gcp)

### Step 3: Deploy Mode (CloudSetupStep)

- [ ] "Connect your [AWS/GCP] account" option shows correct cloud label
- [ ] "Use demo mode" option shows with "Recommended" badge
- [ ] Selecting "cloud" shows runner install curl command
- [ ] Selecting "sandbox" hides runner command
- [ ] Continue triggers install creation
- [ ] Spinner/waiting state shows during install setup
- [ ] Error banner shows if install creation fails

### Step 4: Provisioning (ProvisioningStep)

- [ ] App card shows app name and dynamic progress message
- [ ] Progress ring animates with percentage
- [ ] ETA displays and updates as rows complete
  - Initial ETA uses 90s per row fallback
  - After 10s + 1 completed row, switches to adaptive rate
- [ ] Provisioning rows appear in order:
  1. CloudFormation Stack
  2. Runner
  3. Sandbox
  4. Individual components (varies by app)
- [ ] Each row shows correct status transitions: pending -> active -> done
- [ ] Active rows show blue description text
- [ ] Done rows show green description text with checkmark
- [ ] Runner row (when done) shows: Healthy, Connected/Disconnected, Version
- [ ] Error state: red banner + error icon on failed row
- [ ] Continue button enabled only after workflow finishes successfully
- [ ] "Deploying components" placeholder row appears when infra rows are done but workflow continues

### Step 5: All Set (NextStepsStep)

- [ ] Title is hidden (hideTitle: true)
- [ ] "Your install is live" header with Active status badge
- [ ] Confetti animation fires (useConfetti hook)
- [ ] Three pillar cards render with correct content and icons
- [ ] Learn more links point to correct docs pages
- [ ] Carousel images load for both light and dark mode
- [ ] "View install" button navigates to the install page

## Error Scenarios to Test

### Org Creation Failures
- [ ] Invalid org name (empty, special chars)
- [ ] Duplicate org name
- [ ] Network timeout during org creation

### App Selection Failures
- [ ] API returns empty example apps list
- [ ] Selected slug doesn't match catalog

### Install Creation Failures
- [ ] Sandbox mode unavailable (onboarding_sandbox: false)
- [ ] Cloud mode without runner token
- [ ] Backend returns processing but never resolves

### Provisioning Failures
- [ ] CloudFormation stack fails (IAM permissions)
- [ ] Runner never becomes healthy (timeout)
- [ ] Sandbox provisioning fails (resource limits)
- [ ] Component deploy fails (image pull, helm values)
- [ ] Workflow stuck in-progress indefinitely

### Recovery Scenarios
- [ ] Refresh page mid-provisioning (should resume from current step)
- [ ] Back button during provisioning (should warn or prevent)
- [ ] Re-entering onboarding after partial completion

## ETA Calculation Reference

The provisioning page ETA is computed by `useEta()`:
- **Fallback**: `remainingRows * 90 seconds` (used initially)
- **Adaptive**: After 10s elapsed + at least 1 row done, switches to `(elapsed / doneRows) * remainingRows`
- **Display**: `< 1 min` for under 60s, otherwise `~N min` (rounded up)
