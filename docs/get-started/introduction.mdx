## What Nuon is

Nuon is a deployment platform for software companies that need to run their product inside their customers' cloud accounts, a model called BYOC (bring your own cloud). You package your existing Terraform modules, Helm charts, Kubernetes manifests, and container images as an app template. Nuon installs that template into each customer's AWS, Azure, or GCP account and keeps every install updated from one control plane.

## Does Nuon support my customer's architecture?

Enterprise customers usually ask for a specific deployment architecture. This table answers the common ones. [BYOC architecture patterns](/guides/byoc-architecture-patterns) explains how to build each.

| Install into the customer's existing Kubernetes cluster | [Supported](/guides/byoc-architecture-patterns#existing-customer-kubernetes-cluster) |
| Hybrid: your hosted product stays the control plane, an agent or worker runs next to customer data | [Supported](/guides/byoc-architecture-patterns#agent-or-worker-next-to-customer-data-hybrid-data-plane) |

## How it works

1. **App template.** Your app is TOML config in your own git repo. It defines [components](/concepts/components), [inputs](/concepts/app-inputs), [secrets](/concepts/app-secrets), and a [sandbox](/concepts/sandboxes), the base infrastructure such as a VPC and Kubernetes cluster. See [App templates](/concepts/apps).
2. **Install.** For each customer, Nuon creates an [install](/concepts/installs) and generates a [stack](/concepts/stacks) template (CloudFormation on AWS, Bicep on Azure, Terraform on all three). The customer deploys the stack with their own credentials. It creates the runner and the [operation roles](/concepts/operation-roles) the runner uses.
3. **Runner.** The [runner](/concepts/runners) runs in the customer's account and polls the control plane for jobs. Connections are outbound only, so neither you nor Nuon needs cross-account access to your customer's account. The customer can turn the runner off at any time through the stack.
4. **Updates and operations.** You push config changes to git, and [app branches](/concepts/app-branches) roll them out across installs with plan review and approvals. [Actions](/concepts/actions), [runbooks](/concepts/runbooks), and [policies](/concepts/policies) cover day-2 work.

## Ways to run Nuon

- **Nuon Cloud:** managed, multi-tenant, hosted by Nuon.
- **Nuon BYOC:** a single-tenant control plane in your own AWS or GCP account, operated remotely by Nuon. Requires a paid license.
- **Nuon Self-Hosted:** the same software, operated entirely by you. Open source; a paid license is needed only for support.

See [Choose how to run Nuon](/guides/deployment-options).
