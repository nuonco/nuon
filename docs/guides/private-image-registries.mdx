Nuon pulls private images from ECR, GAR, and ACR using [cloud connections](/guides/cloud-connections). A saved **image repository** maps an exact repository to the pull identity you choose. Assignments select credentials; cloud IAM grants access. Nuon does not apply cloud writes.

1. Create a connection (`ecr`, `gar`, or `acr` preset).
2. Apply the generated setup in your cloud and verify.
3. Register the repository (dashboard or CLI).
4. Save or sync the [container image component](/guides/container-image-components).

Your **vendor cloud admin** applies setup on the **source** registry (not each customer install). Prefer a dedicated identity. Verification checks federation and tokens, not repository pulls — use a metadata fetch or build to confirm access.

Per cloud: [Amazon ECR](/guides/private-image-registries/amazon-ecr) · [Google Artifact Registry](/guides/private-image-registries/google-artifact-registry) · [Azure Container Registry](/guides/private-image-registries/azure-container-registry)

## Add an image repository

1. Open **Settings → Image repositories → Add image repository**.
2. Enter the repository name (no tags or digests):
   - ECR: `acme/api`
   - GAR: repository ID such as `acme-images` (not an image path)
   - ACR: path such as `acme/api`
3. Choose or create a compatible pull identity. Review the derived location, then save.
4. Apply the setup commands from the detail page (additive grants if the identity already exists). Verify the identity.
5. Save or sync the component, then fetch metadata / build to confirm access.

## How image connections are selected

Components do not set `cloud_connection_id`. On save or sync, Nuon looks up the assignment for that exact repository and requires a **verified** connection in the same org with the matching preset and target.

| Registry | Canonical assignment | Connection |
|---|---|---|
| Amazon ECR | `arn:aws:ecr:us-west-2:123456789012:repository/acme/api` | AWS / `ecr`, same account and region |
| Google Artifact Registry | `projects/.../locations/.../repositories/acme-images` | GCP / `gar`, same project and location |
| Azure Container Registry | `acmeimages.azurecr.io/acme/api` | Azure / `acr`, same login hostname |

- Nuon **pins** that connection on the saved config. There is no unique-target fallback — an assignment is always required.
- Changing or removing an assignment does not rewrite old configs. Re-sync to pick up a new identity.
- Delete image-repository assignments before deleting a connection. Old pins keep using a deleted connection until you re-sync.

## Grant access to another repository

1. Add the new repository and select an existing compatible identity (or create another).
2. Apply the **additive** permission commands from the detail page — do not recreate trust.
3. After IAM propagation, verify if needed, then save or sync and test a pull.

| Registry | Additive grant |
|---|---|
| Amazon ECR | Read-only on the exact repo ARNs (`ecr:GetAuthorizationToken` on `*`) |
| Google Artifact Registry | `roles/artifactregistry.reader` on the repositories |
| Azure Container Registry | **Container Registry Repository Reader** (ABAC) on the repository names |

Update cloud IaC if it owns the policy. Run permission updates serially for the same identity.

## API and CLI

Register: `POST /v1/image-repositories` or `nuon image-repositories create --connection-id <id> --repository <repo>`

```json
{
  "cloud_connection_id": "<connection-id>",
  "repository": "arn:aws:ecr:us-west-2:123456789012:repository/acme/api"
}
```

- GAR: `projects/.../locations/.../repositories/...` · ACR: path such as `acme/api`
- `GET` / `DELETE /v1/image-repositories` — delete removes the assignment only (not cloud IAM or historical pins)
- Setup commands: `GET /v1/cloud-connections/{id}/setup?repository=...` (`permissions_cli` for additive grants). Also printed by `nuon image-repositories get|create`
- `nuon cloud-connections` for identities — see [Cloud Connections](/guides/cloud-connections)
