## Day 0: Write your app config

<Note>Find the docs here: [App Templates](/concepts/apps)</Note>

Your app config is TOML in git, so any coding agent can write it.

- Turn your existing Helm charts, Terraform modules, and container images into components, starting from the
  [example app templates](/guides/agents/ai-and-apps).
- Check each file against the app config schema, then run `nuon apps validate` before you push.
- Add [policies](/guides/agents/writing-policies) and install [READMEs](/guides/agents/customizing-readmes) with Nuon's
  skills.

## Day 1: Install for a customer

<Note>Find the docs here: [Customer Installs](/concepts/installs)</Note>

- Set the new install's inputs, such as region or instance size.
- Watch the install workflow as the stack, runner, sandbox, and components come up.
- Review each plan before it applies, and approve it when it looks right.
- When a step fails, read its logs, then retry or skip it.

## Day 2 Operations: Operate your customers' installs

<Note>Find the docs here: [Updates and Operations](/concepts/updates-and-operations)</Note>

- Roll a release out across [install groups](/concepts/app-branches), approving each group's plan.
- Deploy a component and confirm it [stays healthy](/guides/health-checks).
- Run [runbooks](/guides/runbooks) and [actions](/guides/actions) on a customer's install.
- Find which installs are unhealthy or have failing workflows, and why.

Anything that changes an install needs writes enabled and [Admin](/concepts/access-control) on your account. See
[Sample queries](/guides/agents/sample-queries) for prompts, and the [tools catalog](/guides/agents/tools) for everything
your agent can call.
