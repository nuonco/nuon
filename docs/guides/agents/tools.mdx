Writes are hidden from the stdio proxy unless `--allow-writes` is set. Setup examples always include that flag. HTTP MCP lists writes when the identity has [Admin](/concepts/access-control) (`org_admin`).

Timestamps in tool JSON are UTC (Zulu) RFC3339 and end in `Z` (for example `2026-09-04T04:23:00Z`). If you name a calendar day, clock time, or age, convert that UTC instant to the local machine’s timezone first. Do not say “today” or “yesterday” from the UTC date digits. That calendar day can be a day ahead of local time.

List tools return a page (default 20, max 100) plus `has_more`. They do not keep fetching until the full set is loaded. If `has_more` is true, tell the user there are more results and only pass `offset=next_offset` when they need the next page.

For prompts to paste into a client, see [Sample queries](/guides/agents/sample-queries). To connect, see the [MCP walkthrough](/guides/agents/mcp-walkthrough). For skills covering specific tasks, see [Skills](/guides/agents/skills).

## App config

`get_app_config_schema` returns the file schema. When validation is done for this MCP server, use the Nuon CLI binary that started it, for example `nuon-dev apps validate` when the server command is `nuon-dev`, and the same `-C` value when that server was started with `-C`. That match is only for local CLI work done for the MCP server. There is no MCP tool that accepts config file contents.

## Fallback

Use an MCP tool when one covers the operation. When none does, use the Nuon CLI that started this server, including the same `-C` value. When the CLI has no command for it, use `nuon api --raw` if that command is already available. Ask before installing the api extension if missing. Call the HTTP API with curl only as a last resort. The stdio proxy repeats this in its server instructions, with the binary and `-C` filled in.

## Writes

Mutating tools are prefixed with `WRITE OPERATION:` in their descriptions. The stdio proxy hides them unless you pass `--allow-writes`. The identity still needs [Admin](/concepts/access-control) (`org_admin`), not Read-only.

### Destructive tools

These tools carry the MCP `destructiveHint` annotation. The annotation is advisory: your client decides whether to prompt.

| Tool | Requires `confirm: true` |
| --- | --- |
| `deprovision_install` | Yes |
| `deprovision_sandbox` | Yes |
| `reprovision_install` | No |
| `reprovision_sandbox` | No |
| `deploy_install_components` | No |
| `approve_step` | No |
| `reject_step` | No |
| `cancel_workflow` | No |
| `run_runbook` | No |
| `preview_app_branch` | No |

The two deprovision calls are rejected until the agent passes `confirm: true`, and their descriptions tell it to ask you first. `plan_only: true` is exempt, since nothing is applied. You cannot turn this off: `confirm` is an argument on those two tools, not a proxy flag or a client setting.

Write tools that take `role` use an IAM role name from the install's stack. Call `list_available_roles` first (with the matching `operation_type` / `principal_type`) and pass a returned `name`, or omit `role` to use the default. A role the install cannot assume is rejected before any workflow starts, and the error lists the names that are available.
