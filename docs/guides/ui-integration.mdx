With a UI integration, your customers set up your product in their own cloud account from inside your app. They never
open Nuon. Your app talks to Nuon through the [API](/concepts/api) behind the scenes.

<UiIntegrationMock />

This guide covers first-time setup. To change or remove an install later, see
[Add BYOC installation to your product](/guides/control-plane-integration).

## Before you start

- **An API token for your app.** Create a [service account](/concepts/service-accounts) for your app and keep its
  token with your other secrets.
- **A way to run long tasks.** Setup takes several minutes, so run it as a background task in your app.
- **Safe retries.** If a call times out, you can send it again with the same `request_id` without starting a second
  copy. See [Idempotent operations](/guides/idempotent-operations).

## 1. Start the install

An [install](/concepts/installs) is one copy of your product in one customer's account. Create it with the customer's
settings, such as their domain:

```bash
curl -X POST https://api.nuon.co/v1/installs \
  -H "Authorization: Bearer $NUON_API_TOKEN" \
  -H "X-Nuon-Org-ID: $NUON_ORG_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "app_id": "app...",
    "name": "customer-acme",
    "aws_account": { "region": "us-west-2" },
    "inputs": { "domain": "acme.example.com" }
  }'
```

Save the install ID with your customer's record. You'll use it in every later call.

## 2. Customer runs the setup template

Nuon gives each install a setup template, called a [stack](/concepts/stacks). Your customer runs it in their own cloud
account. It creates the network, the permissions, and the [runner](/concepts/runners) that deploys your product.

Get the link with `GET /v1/installs/{install_id}/stack` and show it in your app. On AWS, the `quick_link_url` field
opens the template in the AWS console, ready to run.

Customers often ask what the template creates and what access you get. See
[Positioning safety of BYOC](/guides/vendor-customers) for answers.

## 3. Show progress

Once the template runs, Nuon takes over and deploys your product. Show your customer each stage as it finishes:

1. Account connected
2. Base infrastructure ready, such as the Kubernetes cluster
3. Each part of your product deployed

To know when a stage finishes, either have Nuon notify your app with [webhooks](/guides/webhooks), or check the
install's status every so often.

If a stage fails, show its name and the error message, so your customer and your support team see the same thing.

## 4. Approve changes

Nuon can pause before it changes anything in your customer's account. If you turned that on, approve from your app,
or give your customer one **Approve** button. See
[Approve the provision](/guides/control-plane-integration#approve-the-provision).

## Tips

- **Only get the webhooks you need.** By default, a webhook gets every event in your Nuon org. Filter it to the
  installs and events your app uses.
- **Check that webhooks come from Nuon.** Set a secret on the webhook and check the `X-Nuon-Signature` header. See
  [Verifying signatures](/guides/webhooks#verifying-signatures).
- **Limit the token.** Give the service account the least access that works. See
  [Access control](/concepts/access-control).
- **Name installs after your customer.** Put your own customer ID in the install name, so support can find it quickly.
