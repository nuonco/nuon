A UI integration lets your customers deploy your product into their own cloud account from your app's settings page.
They never see Nuon. Your app calls the Nuon [API](/concepts/api) in the background.

The screens below come from Acme Analytics, an example product. Globex, one of Acme's customers, is setting it up in
Globex's AWS account.

<UiIntegrationMock />

This guide covers first-time setup. To change or remove an install later, see
[Add BYOC installation to your product](/guides/control-plane-integration).

## Before you start

Create a [service account](/concepts/service-accounts) for your app and store its token with your other secrets.
Every call in this guide uses that token.

Setup takes several minutes, and part of it waits on your customer. Run it as a background task in your app, and send
a `request_id` with each call that starts work so a retry after a timeout can't start the same work twice. See
[Idempotent operations](/guides/idempotent-operations).

## 1. Collect the customer's settings

Ask only for what your product needs to run in their account, such as a region and a domain.

<AcmeStartScreen />

When the customer clicks **Start setup**, create an [install](/concepts/installs). An install is one copy of your
product in one customer's account.

```bash
curl -X POST https://api.nuon.co/v1/installs \
  -H "Authorization: Bearer $NUON_API_TOKEN" \
  -H "X-Nuon-Org-ID: $NUON_ORG_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "app_id": "app...",
    "name": "globex",
    "aws_account": { "region": "us-west-2" },
    "inputs": { "domain": "analytics.globex.example.com" }
  }'
```

Save the install ID with the customer's record. You'll need it for every later call.

## 2. Have the customer connect their account

Your customer connects their account by running a setup template, called a [stack](/concepts/stacks), in their own
cloud console. Before they click, tell them what it creates and why. Their security team will ask.

<AcmeTemplateScreen />

Get the template link from `GET /v1/installs/{install_id}/stack` and use it for the button. On AWS, the
`quick_link_url` field opens the template in the AWS console, ready to run.

The template creates the network, the permissions, and the [runner](/concepts/runners), the agent that deploys your
product inside their account. [Positioning safety of BYOC](/guides/vendor-customers) covers the follow-up questions
customers usually ask.

## 3. Show setup progress

Once the template finishes, Nuon deploys your product without any more input from the customer. Show each stage as it
completes, and let them leave the page.

<AcmeProgressScreen />

To find out when a stage finishes, have Nuon call your app with [webhooks](/guides/webhooks), or check the install's
status on a timer. If a stage fails, show its name and error message. Your customer and your support team then see the
same thing.

## 4. Ask the customer to approve changes

You can set installs to pause before Nuon changes anything in the customer's account. If you do, show the customer
what will change and let them approve it.

<AcmeApproveScreen />

Wire the **Approve** button to `approve-all` on the install's workflow. See
[Approve the provision](/guides/control-plane-integration#approve-the-provision).

## Tips

- Filter your webhooks. By default, a webhook receives every event in your Nuon org, so limit it to the installs and
  events your app uses.
- Check that each webhook request came from Nuon. Set a secret on the webhook and verify the `X-Nuon-Signature`
  header. See [Verifying signatures](/guides/webhooks#verifying-signatures).
- Give the service account the least access that works. See [Access control](/concepts/access-control).
- Name each install after your customer, using your own customer ID, so support can find it in the Nuon dashboard.
