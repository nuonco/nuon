### Control Plane Syncing via App Branches
Previously, running `nuon apps sync` built, validated, and synced your config directly from your CLI. This frequently led to version mismatches and compatibility issues between your CLI version and the control plane.

With App Branches, Nuon directly fetches your config repo and syncs it from the control plane. This unlocks features like automated previews and complex rollouts.

### Install Groups
Rollouts were previously managed on an install-by-install basis. With Install Groups, you can define multi-install deployment plans and orchestrate the update sequence across installs using labels or version pinning.

### Native Automation & Triggers
You can now natively trigger updates to your installs using:
* Git pushes
* Git tags
* Pull Request (PR) labels
* Manual runs

Automate these triggers using a GitHub Webhook or the GitHub Action (GHA).

### Previews
Validate changes before merging to production. When you open a pull request or create a feature branch, you can preview changes in three distinct modes:
1. Build and Validate: Validates your config and builds your components.
2. Plan Only: Previews deploys and updates against a single install without applying changes.
3. Apply: Runs and executes changes on a single test install.

<Note>
  For setup details, see our [docs on previews](/guides/app-branches#previews).
</Note>

## Step 1: Create Your First App Branch

Create an app branch using one of the two methods below:

### Option A: Via the CLI
Run `nuon apps sync` with the feature flag enabled (we'll do this). Nuon will guide you through initializing an app branch from your local repo and attaching your existing installs to it.

```bash
nuon apps sync
```

### Option B: Via TOML Config
Alternatively, define your app branch in a `branch.toml`.

<Note>
  See [examples and layouts](/guides/app-branches#write-a-branch-config).
</Note>

## Step 2: Verify Your First Run

After creating your app branch, verify that the it can sync and build your application:

1. Trigger a run on your app branch, this will validate your config can load and your components can build successfully.

## Step 3: Update Installs to App Branches

1. Add installs to your app branch.
2. Execute a run to update your installs.
3. Update your install configs to point at your new app branches.

## Next Steps & Advanced Setup

Now that your base migration is complete, expand your setup with these advanced features:

* Set up [GitHub Actions](/guides/github-actions#trigger-a-branch-run-from-your-workflow) for Branch Syncing
* Automate deployment group rollouts with git pushes, tags, or PR labels
* Set up [pull request previews](/guides/app-branches#previews) that comment and set checks on your PRs
