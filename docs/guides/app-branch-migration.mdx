### Control Plane Syncing via App Branches
Previously, running `nuon apps sync` validated, synced, and built your app template directly from the Nuon CLI.

With App Branches, Nuon directly fetches your app template Git repository and syncs it to the Nuon control plane. This unlocks features like automated previews and install rollouts.

### Install Groups
Rollouts were previously managed on an install-by-install basis using the Nuon CLI or dashboard. With App Branches, installs are aggregated into Install Groups which are vendor-defined ways to rollout upgrades to similar installs.

See more in the [App Branches docs](/concepts/app-branches#structuring-branches-and-install-groups).

### Native Automation & Triggers
You can now natively trigger updates to your installs using:
* Git pushes
* Git tags
* Pull Request (PR) labels
* Manual runs

Automate these triggers using a GitHub Webhook or the [GitHub Action (GHA)](/guides/github-actions#trigger-a-branch-run-from-your-workflow).

See more in the [App Branches docs](/concepts/app-branches#what-triggers-an-app-branch-run).

### Previews
Validate changes to your app template's git branch before merging to the git branch in your app branch. When you open a pull request or create a feature branch, you can preview changes in three distinct modes:
1. Build and Validate: Validates your config and builds your components.
2. Plan Only: Previews deploys and updates against a single install without applying changes.
3. Apply: Runs and executes changes on a single test install.

<Note>
  For setup details, see our [docs on previews](/guides/app-branches#previews).
</Note>

## Step 1: Create Your First App Branch

Create an app branch using one of the two methods below:

### Option A: Via the CLI
Run `nuon apps sync` with the feature flag enabled (we'll do this). Nuon will guide you through initializing an app branch from your local repo and attaching your existing installs to it.

```bash
nuon apps sync
```

### Option B: Via TOML Config
1. Add a `branch.toml` to your app template.
2. Sync it to the Nuon control plane with `nuon branches sync`.

<Note>
  See [examples and layouts](/guides/app-branches#write-a-branch-config).
</Note>

## Step 2: Verify Your First Run

Nuon automatically starts the first branch run on sync, which pulls the app template and builds the sandbox and components. Confirm that run succeeds.

## Step 3: Update Installs to App Branches

1. Add [labels](/guides/install-configs#labeling-installs) to your installs or [install configs](/guides/install-configs#install-configs) so they join an install group on the app branch.
2. Push to the app branch’s tracked git branch to roll the update out to those installs.

## Next Steps & Advanced Setup

Now that your base migration is complete, expand your setup with these advanced features:

* Set up [GitHub Actions](/guides/github-actions#trigger-a-branch-run-from-your-workflow) for Branch Syncing
* Automate deployment group rollouts with git pushes, tags, or PR labels
* Set up [pull request previews](/guides/app-branches#previews) that comment and set checks on your PRs
