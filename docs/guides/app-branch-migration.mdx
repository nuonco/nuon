[App Branches](/concepts/app-branches) provide change management for apps.
They allow you to manage creating and rolling out new versions of an app in a controlled way.

For new orgs, App Branches are the only way to package and deploy app changes.
If your org predates App Branches, `nuon apps sync` will continue to work, but we recommend migrating as soon as possible.
This guide will walk you through the migration process.

## What's changing

With `nuon apps sync`, the CLI validates, syncs, and builds your app template directly from your machine or CI runner.
With App Branches, Nuon fetches your app template from your Git repo, builds and packages the new app version, and rolls it out to installs.
`nuon apps sync` keeps working for any install that isn't on an App Branch yet, so you can move installs over in batches rather than all at once.

## Before you start

Before getting started, you will need the following in place.

- An app template in a Git repository.
- If the template, sandbox, or any component repositories are private, [connect the Nuon GitHub App](/guides/vcs) to grant access to clone them.
- If you use config files, the [Nuon CLI](/cli) installed and authenticated (`nuon auth login`), with the app selected (`nuon apps select`).

## Shortcut: migrate with `nuon apps sync`

The CLI can create the App Branch and move your installs for you:

1. Ask Nuon to enable App Branch migration for your org. This turns off `nuon apps sync` for every app in the org, so installs you haven't moved stay on the app template you last synced.
2. In your app template directory, run `nuon apps sync` in an interactive terminal. The directory must be a Git checkout with a GitHub `origin` remote.
3. Confirm **Create an app branch now?**, choose the App Branch name, and confirm writing and syncing the branch config file at `branches/<name>.toml`.
4. Once the first branch run finishes, confirm **Add installs to app branch "&lt;name&gt;"?** and choose **All**, or choose installs one at a time.
5. Commit and push the branch config file.

The branch config file the CLI writes has no Install Groups, so every install lands in a single `default` group.
To roll out in stages, add Install Groups as shown in Step 1 and sync the branch config file with `nuon branches sync`.
Then continue from Step 4.

## Step 1: Create the App Branch

<Tabs>
  <Tab title="Config file">
    Create a branch config file in a folder named `./app-branches`, alongside your app template directory.

    ```toml app-branches/main.toml
    name = "main"

    [connected_repo]
    repo      = "acmeco/my-app-template"
    directory = "."
    branch    = "main"

    [run]
    mode = "push"

    [[install_groups]]
    name  = "stage"
    order = 1
    [install_groups.label_selector]
    env = "stage"

    [[install_groups]]
    name    = "production"
    order   = 2
    default = true
    [install_groups.label_selector]
    env = "prod"
    ```

    Exactly one Install Group must set `default = true`.
    See [Configure App Branches](/guides/app-branches#write-a-branch-config) for details on every field, and [structuring branches and Install Groups](/concepts/app-branches#structuring-branches-and-install-groups) for deployment plans beyond a single staged rollout.

    <Note>
      While you migrate, keep branch config files out of your app template directory.
      `nuon apps sync` will refuse to run if it finds a `branch.toml` or `branches/` folder there.
      Once you stop running `nuon apps sync`, you can move branch config files to `branches/`.
    </Note>

    Sync the branch config file:

    ```sh
    nuon branches sync --file app-branches/main.toml --confirm
    ```
  </Tab>
  <Tab title="Dashboard">
    1. Open the app's **Branches** page and click **Create branch**.
    2. Enter a **Branch name**. Leave **Connect to git repository** checked, select the **VCS connection**, **Repository**, and **Git branch** of your app template, and set the **Directory** that contains it. Click **Create branch**.
    3. On the branch's **Settings** tab, click **Edit plan**. The branch starts with one group, named `Default`.
    4. Rename `Default` to `production`, then click **Add group** and name the new group `stage`.
    5. On each group, select **Labels**, type a label such as `env=stage`, and press Enter.
    6. Put `stage` first with **Move up** in the group's menu.
    7. Leave **Default group** checked only on `production`, then click **Save changes**.
  </Tab>
</Tabs>

## Step 2: Confirm the first run

Creating the branch starts its first run automatically. The run fetches the tracked branch, reads the app template, creates a new app version from it, and builds components and the sandbox.
No installs are on the branch yet, so the run skips the Rollout phase.

## Step 3: Assign installs to the App Branch

Installs can be assigned to an App Branch with an [install config file](/guides/install-configs) or in the Dashboard.

We recommend assigning installs in batches, in the same order as your Install Groups (for example, staging before production).
Assigning an install updates it to the branch's latest app version immediately.
Moving one batch at a time lets you confirm each batch deployed cleanly before you move the next.
Installs you haven't moved keep deploying from the app template last synced with `nuon apps sync`.

<Tabs>
  <Tab title="Config file">
    Set `app_branch` in the install config file of each install in your first Install Group, then sync them:

    ```toml installs/acme-stage.toml highlight={2}
    name       = "acme-stage"
    app_branch = "main"

    [labels]
    env = "stage"
    ```

    ```sh
    nuon installs sync -d installs/acme-stage.toml --app-id <your-app-id> --confirm
    ```

    Once those installs have deployed, do the same for the next Install Group:

    ```toml installs/customer-acme.toml highlight={2}
    name       = "customer-acme"
    app_branch = "main"

    [labels]
    env = "prod"
    ```

    ```sh
    nuon installs sync -d installs/customer-acme.toml --app-id <your-app-id> --confirm
    ```

    Confirm where each install landed in the `BRANCH` column:

    ```sh
    nuon installs list --app-id <your-app-id>
    ```

    <Note>
      If a sync moves an install and sets an input that only exists on the branch's app template in the same call, it
      fails with `unknown input(s): <name>`. Move the install first, then set the new input in a second
      `nuon installs sync`.
    </Note>
  </Tab>
  <Tab title="Dashboard">
    Open the page of each install in your first Install Group:

    1. In the install's header, click the edit button next to its branch.
    2. Under **Select destination branch**, select the App Branch.
    3. Under **Deployment group**, select the install's Install Group. For any group other than the default, choose **Add group labels to install**.
    4. Click **Move and reconcile**.

    Once those installs have deployed, do the same for the next Install Group.
    Confirm where each install landed in the **Branch** column of the app's **Installs** page.
  </Tab>
</Tabs>

## Step 4: Update your automation

If you have automation using `nuon apps sync`, you can remove it once every install is on an App Branch.

If you want to use your own automation to trigger branch runs instead, set the run mode to `manual_only` in the branch config file, so pushes no longer start runs:

```toml app-branches/main.toml highlight={9}
name = "main"

[connected_repo]
repo      = "acmeco/my-app-template"
directory = "."
branch    = "main"

[run]
mode = "manual_only"
```

Sync the branch config file with `nuon branches sync`, then use the CLI in your automation to trigger runs.
The example below uses the official [Nuon GitHub Action](/guides/github-actions#trigger-a-branch-run-from-your-workflow) to replace a `nuon apps sync` step:

```yaml .github/workflows/sync.yaml
on:
  push:
    branches:
      - main

permissions:
  contents: read
  id-token: write

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Sync app template # [!code --]
      - name: Trigger branch run # [!code ++]
        uses: nuonco/actions-nuon@v0.5.0
        with:
          org_id: ${{ vars.nuon_org_id }}
          app_id: ${{ vars.nuon_app_id }}
          command: "apps sync" # [!code --]
          command: "branches trigger --branch-id main --no-wait" # [!code ++]
```

## Step 5 (optional): Configure Previews

App Branches support testing pull requests against a single install before they merge, using [Previews](/guides/app-branches#previews).

<Tabs>
  <Tab title="Config file">
    Add a `[preview]` block to the branch config file:

    ```toml app-branches/main.toml
    name = "main"

    [preview] # [!code ++:5]
    mode = "plan-only"

    [preview.label_selector]
    preview = "true"
    ```

    Add a dedicated preview install carrying that label to its install config file:

    ```toml installs/acme-preview.toml
    name       = "acme-preview"
    app_branch = "main"

    [labels]
    preview = "true"
    ```

    Sync both the branch config file and the install config file.
  </Tab>
  <Tab title="Dashboard">
    1. Assign a dedicated preview install to the App Branch, as in Step 3.
    2. On the branch's **Settings** tab, click **Edit preview defaults**.
    3. Turn on **Enable automated previews**, set **Default mode** to **Plan only**, and select the preview install as the **Default install**. Click **Save changes**.
  </Tab>
</Tabs>

Then open a pull request against the tracked branch.
Nuon plans against the preview install and comments on the pull request with the result.
See [Previews](/guides/app-branches#previews) for more details.
