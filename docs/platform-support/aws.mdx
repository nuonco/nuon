## Configuration

To deploy an app to AWS, configure it to use an AWS sandbox and runner. We provide a minimal sandbox you can use to get started. You will need to set some vars to configure the sandbox. Create inputs for the public and private domains, since those will be different for each install. You will also need to set some IAM roles to grant the runner access to the EKS cluster.

```toml sandbox.toml
# sandbox

terraform_version = "1.11.3"

[public_repo]
directory = "."
repo      = "nuonco/aws-eks-karpenter-sandbox"
branch    = "main"

[vars]
cluster_version = "1.33"
cluster_name    = "n-{{.nuon.install.id}}"
public_root_domain   = "{{ .nuon.inputs.inputs.root_domain }}"
internal_root_domain = "internal.{{ .nuon.inputs.inputs.root_domain }}"

[[var_file]]
contents = "./sandbox.tfvars"
```

```toml sandbox.tfvars
maintenance_role_eks_access_entry_policy_associations = {
  eks_admin = {
    policy_arn = "arn:aws:eks::aws:cluster-access-policy/AmazonEKSAdminPolicy"
    access_scope = {
      type = "cluster"
    }
  }
  eks_view = {
    policy_arn = "arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy"
    access_scope = {
      type = "cluster"
    }
  }
}
```

```toml runner.toml
# runner

runner_type = "aws"
helm_driver = "configmap"
```

## Installation

When you create a new install, Nuon generates the install stack your customer uses to provision the runner and base infrastructure in their AWS account. Every AWS install gets a one-click console link, and the same resources are also available as Terraform, so your customer can use whichever fits their tooling:

- **CloudFormation** — a generated CloudFormation template with a [quick-create link](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-console-create-stacks-quick-create-links.html) that opens the AWS console with the template and stack name prefilled, plus an AWS command-line interface (CLI) `create-stack` command.
- **Terraform** — the published [`nuonco/stack/aws`](https://registry.terraform.io/modules/nuonco/stack/aws/latest) module (recommended, feature flag), or generated `inputs.auto.tfvars` and `secrets.auto.tfvars` files for the open-source [`install-stacks/aws`](https://github.com/nuonco/install-stacks) module.

Both formats describe the same set of resources (IAM operation roles, secrets, and trust to the Nuon control plane), so installs end up in the same state regardless of which one your customer runs.

For a side-by-side view of what customers do on each cloud, see [Stacks](/concepts/stacks#what-your-customer-does-on-each-cloud).

### Create an Install

Navigate to the Installs tab in the Nuon dashboard, click "Create Install", and select the app you want to install.

This kicks off a provision workflow. The CloudFormation template and the Terraform files are templated with the install ID, region, and other settings. The provision workflow's **await install stack** step exposes them as tabs (**CloudFormation**, **Terraform**, and **TF Module** where enabled), which can be shared with your customer.

### Install the Stack

Your customer must log into the AWS account they want to install your app in, and ensure they have the required permissions.

#### Option 1: CloudFormation

Either:

- Open the **Quick launch in AWS console** link in a browser and complete the web flow. If the install has no region pinned, the link opens in whichever region the console currently has selected, so switch to the intended region first. See [Provision Stacks with CloudFormation](/guides/provision-stacks-with-cloudformation).
- Run the provided **AWS CLI** `create-stack` snippet ([install the AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) first).

#### Option 2: Terraform

From the **TF Module** tab, add the published module to an existing Terraform project and apply it with an API token. See [Provision Stacks with a Terraform Module](/guides/provision-stacks-with-terraform-module).

Or, from the **Terraform** tab:

1. Download the generated `inputs.auto.tfvars` and `secrets.auto.tfvars` files.
2. Create a `backend.tf` to store Terraform state (an S3 snippet is provided in the dashboard).
3. Run `terraform init && terraform apply` against the [`install-stacks/aws`](https://github.com/nuonco/install-stacks) module. Both `.auto.tfvars` files are loaded automatically.

Custom resources from CloudFormation nested stacks are not translated automatically. If you extend the install stack with custom CloudFormation resources, fork [`install-stacks`](https://github.com/nuonco/install-stacks) and make the equivalent Terraform changes there.

## Updating

If you make changes to the install stack, the install must be reprovisioned.

1. From the install's Overview page, click "Reprovision install" in the "Manage" drop-down. This triggers a reprovision workflow.
1. A new CloudFormation template and Terraform tfvars are generated.
1. Send the updated Quick-Create URL / CLI command, or the new `inputs.auto.tfvars` and `secrets.auto.tfvars` files, to your customer.
1. Customers using Terraform re-run `terraform apply` against the same backend.
