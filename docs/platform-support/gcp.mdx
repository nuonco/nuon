## Configuration

To install an app template on GCP, configure it to use a GCP sandbox and runner. We provide a [GKE sandbox](https://github.com/nuonco/gcp-gke-sandbox) you can use to get started, which provisions a GKE cluster and the IAM bindings the runner needs. Create inputs for the public and private domains, since those will be different for each install.

```toml sandbox.toml
# sandbox

terraform_version = "1.11.3"

[public_repo]
directory = "."
repo      = "nuonco/gcp-gke-sandbox"
branch    = "main"

[vars]
cluster_name         = "n-{{.nuon.install.id}}"
public_root_domain   = "{{ .nuon.inputs.inputs.domain }}"
internal_root_domain = "internal.{{ .nuon.inputs.inputs.domain }}"

[[var_file]]
contents = "./sandbox.tfvars"
```

```toml sandbox.tfvars
additional_namespaces = ["whoami"]
```

```toml runner.toml
# runner

runner_type = "gcp"
helm_driver = "configmap"
```

## Installation

When you create an install, Nuon generates a Terraform install stack. Your customer applies it in their GCP project to
create the runner and base infrastructure. They can run Terraform themselves or through Google Cloud's
[Infrastructure Manager](https://cloud.google.com/infrastructure-manager/docs).

### Create an Install

In the Nuon dashboard, open the Installs tab, click **Create Install**, and select the app you want to install.

This starts a provision workflow. Its **Await install stack** step shows how to apply the stack, with the **TF Module**
tab selected by default.

### Install the Stack

The recommended path is the published [`nuonco/stack/gcp`](https://registry.terraform.io/modules/nuonco/stack/gcp)
module. Your customer adds the snippet from the **TF Module** tab to their own Terraform project, sets their Nuon
credentials and secret values as environment variables, and runs:

```bash
terraform init && terraform apply
```

On the first apply, the snippet passes `project_id` and `region` to the module, because the control plane hasn't
recorded the install's project yet. Your customer can drop them once the install is provisioned.

See [Provision Stacks with a Terraform Module](/guides/provision-stacks-with-terraform-module) for every step,
including credentials and secrets.

<Note>
  The **Terraform** tab still offers the legacy flow: clone `install-stacks/gcp` and apply generated
  `inputs.auto.tfvars` and `secrets.auto.tfvars` files. See
  [Provision Stacks with Terraform](/guides/provision-stacks-with-terraform).
</Note>

## Try it with a sample app

We maintain [`gke-simple`](https://github.com/nuonco/example-app-configs/tree/main/gke-simple), a sample app that uses the GKE sandbox to deploy a `whoami` workload with a certificate and load balancer.

To try it:

- Install the [CLI](../cli)
- Clone the [example apps repo](https://github.com/nuonco/example-app-configs)
- `cd` into the `gke-simple` directory
- Run `nuon auth login`
- Run `nuon apps create -n gke-simple`
- Add `branches/main.toml` with a `[public_repo]` block pointing at `nuonco/example-app-configs`, directory
  `gke-simple`, branch `main` (see [Configure app branches](/guides/app-branches))
- Run `nuon branches sync --file branches/main.toml`, which creates the branch and starts its first run
- Open the Nuon dashboard and create an install

## Updating

If you make changes to the install stack template, the install must be reprovisioned to update the stack.

1. From the install's Overview page, click on "Reprovision install" in the "Manage" drop-down menu. This will trigger a reprovision workflow.
1. A new stack version is generated.
1. Your customer runs `terraform apply` again. With the module, the new version is picked up on the next plan. With the
   legacy flow, send them the updated `inputs.auto.tfvars` and `secrets.auto.tfvars` files first.

See [Updating the stack](/guides/provision-stacks-with-terraform-module#updating-the-stack) for input, secret, and role
changes.
