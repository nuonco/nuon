How app branch connections work

An install belongs to exactly one app branch, and that branch places it in exactly one deployment group. Ownership is a row in an append-only connection ledger, not a column on the install.

1 install → 1 branch 1 branch → 1 group per install Move deactivates, then appends

The shape

Install.app_branch_id and app_branch_group still appear on the API. They are derived from the active connection after the row is loaded. The source of truth is InstallAppBranchConnection.

How an install lands in a group

Groups describe how to match, they do not list install IDs. Resolution runs whenever the install is created, moved, or has labels changed, and whenever the branch config changes. An install can only belong to one group on a branch.

explicit group

If the install names app_branch_group, that group wins. Naming a group that does not exist on the branch is an error. Source recorded as explicit.

Then
label_selector

Match the install’s labels against each group. Matching two groups is an error. Source recorded as labels.

Then
default group

The single group flagged default catches every remaining install the branch owns. Source recorded as default.

→
Otherwise
error

The install does not match any group and the branch has no default. Create, move, and label changes refuse rather than leaving it ungrouped.

Branch config rules: group names are unique; every group is either default or has a label_selector, never both; at most one default per branch. Install config: app_branch_group requires app_branch.

What changes a connection

Changing branch or group deactivates the current row and appends a new one. There is no way to take an install off a branch without naming another branch.

Create

Create with app_branch (and optional app_branch_group). Resolve the group, then write the install and the first connection in one transaction.

Move

PATCH /v1/installs/{id}/app-branch first checks the destination has a completed, non-preview run to deploy, then deactivates the old row, appends a new one, and enqueues an update.

Labels

Adding or removing labels never changes which branch owns the install. It re-resolves the group on that branch. Two matching groups is still an error.

Branch config

Saving a new branch config reconciles every install the branch already owns. Explicit group names stay put if they still exist; label-matched installs can move groups.

What a branch run does with those connections

A branch run does not pick installs off the app. Each group step starts from the installs the branch owns, then keeps only those that resolve into that group.

Plan steps wait for approval. Deploy steps create one install config update workflow per install in the group and track them on an InstallGroupRun. Groups run in order, so canary finishes before rest starts.

Containment: a group can never reach an install another branch owns, even if its label selector would match. Resolve always starts from BranchInstalls.
