An App Template is a series of TOML files that describe how your app is structured and what it depends on.
Each [install](/concepts/installs) is one deployment of an App Template. Most teams keep one template per cloud or
architecture, such as AWS and Azure.

## What's in a template

A template is a directory of TOML files in your own git repo. The [configuration reference](/config-ref) covers
each file.

```
my-app/
├── metadata.toml   # name and README
├── inputs.toml     # customer values
├── secrets.toml    # customer credentials
├── policies.toml   # policy checks
├── components/     # your product
├── actions/        # scripts
├── runbooks/       # procedures
│
│   # Nuon infrastructure
├── stack.toml      # install stack
├── runner.toml     # runner settings
└── sandbox.toml    # VPC, cluster
```

- **[Metadata](/config-ref/metadata)**: the template's name and README.
- **[Inputs](/concepts/app-inputs)**: values each customer sets, such as region.
- **[Secrets](/concepts/app-secrets)**: credentials each customer supplies.
- **[Policies](/concepts/policies)**: checks that run before a build or deploy.
- **[Components](/concepts/components)**: your Helm charts, Terraform modules, manifests, and images.
- **[Actions](/concepts/actions)**: scripts you run against installs.
- **[Runbooks](/guides/runbooks)**: multi-step procedures for installs.

[Nuon infrastructure](/concepts/nuon-infrastructure):

- **[Stack](/concepts/stacks)**: what the customer applies first, such as the network and permissions.
- **[Runner](/concepts/runners)**: settings for the runner in each customer's account.
- **[Sandbox](/concepts/sandboxes)**: base infrastructure, such as a VPC and cluster.

## How a template changes

Push to git. An [app branch](/concepts/app-branches) rolls the change out to your installs.
