---
title: "Sandboxes"
description: "Sandboxes manage the base infrastructure layer for your application in each customer's cloud account."
---

A Sandbox is the base infrastructure layer provisioned in each install. It creates a consistent, isolated environment that your application can rely on regardless of the customer's account.

Sandboxes typically include networking (VPC, subnets), compute (Kubernetes cluster, VMs), and IAM roles. In a shared responsibility model, a customer can provide existing infrastructure like a VPC or Kubernetes cluster through [inputs](/concepts/app-configuration#inputs).

## Nuon Managed Sandboxes

Nuon maintains managed sandbox templates for common configurations. Each is published as a GitHub repository that you reference in your `sandbox.toml`:

- [AWS EKS sandbox](https://github.com/nuonco/aws-eks-sandbox)
- [AWS EKS with Karpenter sandbox](https://github.com/nuonco/aws-eks-karpenter-sandbox)
- [AWS Min sandbox](https://github.com/nuonco/aws-min-sandbox)
- [Azure AKS sandbox](https://github.com/nuonco/azure-aks-sandbox)

<Note>
The AWS Min sandbox does not create a Kubernetes cluster, but still provisions a Route 53 Zone and IAM roles for the install.
</Note>

You can also fork these or create your own custom sandbox. See the [Configuring Sandboxes](/guides/configuring-sandboxes) guide for details.

## Sandbox Outputs

Sandbox outputs are accessible to all components through [variables](/guides/using-variables). For example:

```toml components/app.toml
[values]
account_region = "{{.nuon.install.sandbox.outputs.account.region}}"
```

See the [outputs.tf](https://github.com/nuonco/aws-eks-sandbox/blob/main/outputs.tf) for a full list of available outputs for each sandbox.
