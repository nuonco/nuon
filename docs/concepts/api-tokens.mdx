An **API token** authenticates requests to the [Nuon Control Plane API](/concepts/api). Use one to call the API, drive the CLI in CI/CD, or integrate Nuon into your own product.

## Token types

- **Service account token** — the supported kind of API token. The token belongs to a [service account](/concepts/service-accounts) and acts as that account, with the account's role, in the current org only. Create a service account with the role you want, then create one or more tokens for it.
- **Personal token** (legacy, deprecated) — a token issued against a person's own account. Personal tokens are deprecated because they carry all of their creator's access, in every org that person belongs to. Existing personal tokens keep working until they are revoked; org admins can find and revoke them in the dashboard under **Settings → API tokens**, in the legacy personal tokens section.

## Token properties

| Property | Description |
| --- | --- |
| **Name** | A human-readable label to identify the token. Defaults to the service account's identity. |
| **Duration** | How long the token is valid. Defaults to `8760h` (one year). |

A token's permissions come from its service account's role. See [Access control](/concepts/access-control) for the available roles.

Creating and managing API tokens requires **org admin** access.

## Managing tokens

In the dashboard, go to **Settings → API tokens** to see and revoke the tokens in the org.

In the CLI, tokens are managed through [service accounts](/concepts/service-accounts). A token's access comes from the account it belongs to, so you create a service account with the role you want, then create tokens for it.

### Creating a token

Create a service account with a role, then create a token for it:

```sh
nuon service-accounts create --name ci --role org_read_only
nuon service-accounts tokens create --id <account-id> --name ci-token
```

Tokens expire after one year by default. Use `--duration` to change that:

```sh
nuon service-accounts tokens create --id <account-id> --name ci-token --duration 720h
```

<Note>
Tokens are shown **only once** at creation time. Store the value somewhere safe (a secret manager or CI secret); you cannot retrieve it again later.
</Note>

### Listing tokens

List every service account token in the org:

```sh
nuon service-accounts tokens list
```

Only list the tokens for one service account:

```sh
nuon service-accounts tokens list --id <account-id>
```

Search tokens by name or ID:

```sh
nuon service-accounts tokens list --search ci
```

Token secrets are never returned.

### Revoking tokens

Delete a token to revoke its access immediately:

```sh
nuon service-accounts tokens delete --token-id <token-id>
```

<Note>
The `nuon orgs api-tokens` commands are deprecated. They still work, but print a warning pointing to the commands above.
</Note>

## Using a token

To use a token, include it in API requests as a Bearer credential in the `Authorization` header:

```sh
curl https://api.nuon.co/v1/current-user \
  -H "Authorization: Bearer <your-api-token>"
```

You can also use a token with the CLI by setting it as the value of the `NUON_API_TOKEN` environment variable or the `api_token` config value.

<CodeGroup>
```sh env
export NUON_API_TOKEN=<your-api-token>
```

```sh ~/.nuon
api_token: <your-api-token>
```
</CodeGroup>
