An **API token** authenticates requests to the [Nuon Control Plane API](/concepts/api). Use one to call the API, drive the CLI in CI/CD, or integrate Nuon into your own product.

## Token types

- **Service account token** — the supported kind of API token. The token belongs to a [service account](/concepts/service-accounts), with an explicit role and org/app/install scope in one org. Its immutable permission ceiling can be narrower than the account's current bindings. Create a service account, then create one or more separately scoped tokens for it.
- **Personal token** (legacy, creation retired) — a token issued against a person's own account. Replace personal tokens with service-account tokens. Org admins can still inventory and revoke existing personal tokens through the legacy static-token endpoints.

<Note>
The v3 cutover requires explicit persisted credential limits. Existing tokens are not automatically upgraded by issuing new ones. Historical tokens require independently evidenced original limits during offline migration, or replacement before activation. Current account roles do not prove historical token permissions. Clients must adopt the explicit role/scope request before cutover; the backend change alone does not update the CLI, SDKs or dashboard.
</Note>

## Token properties

| Property | Description |
| --- | --- |
| **Name** | A human-readable label to identify the token. Defaults to the service account's identity. |
| **Duration** | Positive lifetime, at most `8760h` (one year), which is also the default. Non-interactive issuers cannot issue beyond their own expiry. |
| **Role** | Required customer role defining the permission ceiling. |
| **Scope** | Required org, app or install target matching the role's kind. |

A token can act only where both its frozen ceiling and the account's live bindings allow it. Later promotion does not expand an existing token; removing a binding removes that access immediately. See [Access control](/concepts/access-control) for all nine roles.

Creating and managing API tokens requires **Org Admin** authority allowed by the caller's credential limits. Issuance also checks that the entire requested role at the target fits both the caller's authority and the service account's grants. App/Install Admin cannot delegate. Managed workload identities use their owning issuer instead.

## Managing tokens

In the dashboard, go to **Settings → API tokens** to see and revoke the tokens in the org.

Tokens are managed through [service accounts](/concepts/service-accounts). The supported issuance API is `POST /v1/tokens`; clients that omit role or scope must be updated before cutover.

### Creating a token

Create a service account with a suitable binding using `POST /v1/service-accounts`, then request the token's role and scope explicitly:

```sh
curl https://api.nuon.co/v1/tokens \
  -H 'Authorization: Bearer <org-admin-credential>' \
  -H 'X-Nuon-Org-ID: <org-id>' \
  -H 'Content-Type: application/json' \
  -d '{"account_id":"<account-id>","role":"app_reader","scope":{"kind":"app","id":"<app-id>"},"name":"acme-ci","duration":"720h"}'
```

`scope.org_id` defaults to the selected org. The target must belong to that org. Omission of `scope` does not default to org-wide access. Use `invalidate: true` to revoke the service account's existing credentials and their descendants atomically with replacement; if issuance fails, revocation is rolled back.

<Note>
Tokens are shown **only once** at creation time. Store the value somewhere safe (a secret manager or CI secret); you cannot retrieve it again later.
</Note>

### Listing tokens

List every service account token in the org:

```sh
nuon service-accounts tokens list
```

Only list the tokens for one service account:

```sh
nuon service-accounts tokens list --id <account-id>
```

Search tokens by name or ID:

```sh
nuon service-accounts tokens list --search ci
```

Token secrets are never returned.

### Revoking tokens

Delete a token to revoke its access immediately:

```sh
nuon service-accounts tokens delete --token-id <token-id>
```

<Note>
The legacy `POST /v1/account/static-token` and `POST /v1/service-accounts/:account_id/tokens` creation endpoints are retired and return `410 Gone`. Commands using those endpoints must migrate to `POST /v1/tokens`. Legacy inventory and revocation remain available.
</Note>

## Using a token

To use a token, include it in API requests as a Bearer credential in the `Authorization` header:

```sh
curl https://api.nuon.co/v1/current-user \
  -H "Authorization: Bearer <your-api-token>"
```

You can also use a token with the CLI by setting it as the value of the `NUON_API_TOKEN` environment variable or the `api_token` config value.

<CodeGroup>
```sh env
export NUON_API_TOKEN=<your-api-token>
```

```sh ~/.nuon
api_token: <your-api-token>
```
</CodeGroup>
