---
title: "Actions"
description: "Automate operational tasks and workflows in installs."
---

Actions are reusable scripts that can be run in installs. Each action consists of a trigger that determines when it runs and one or more steps that define what it does.

Actions can be used for:

- Database migrations
- Health checks
- Maintenance scripts
- Diagnostic information collection

## Triggers

Actions can be triggered manually via the dashboard or CLI, on a cron schedule, or in response to install lifecycle events (e.g., `post-provision`, `pre-deploy-component`).

## Permissions

Actions run with the same permissions as the [Runner](/concepts/runners) in each install. For elevated access, actions can use [break glass roles](/config-ref/break-glass) that the customer enables through the [Stack](/concepts/stacks).

<Note>
We maintain a [collection of commonly-used actions](https://github.com/nuonco/actions) in an open-source repo to get started with.
</Note>

For configuration details, triggers reference, and examples, see the [Actions guide](/guides/actions).
