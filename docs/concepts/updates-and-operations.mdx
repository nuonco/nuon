Because App Templates live in git, an update is a push. Once an install is running, Nuon gives you the tools to keep it
healthy.

An update can be a new release of your product, a component upgrade, or an infrastructure change such as a new
Kubernetes version. Every install group waits on a plan approval by default. You can
[auto-approve plans](/concepts/workflows#workflow-approvals) on an install, or let a group approve itself when every
policy check passes.

When a fix needs more access than the runner normally has, the customer turns on an
[elevated role](/concepts/operation-roles#elevated-access-and-break-glass-operations) for the task, then turns it off
again. Every use shows up in their audit logs.
