## Push updates

Because App Templates live in git, an update is a push. A push to the tracked branch starts a branch run that builds
what changed, then plans and deploys it across your installs one
[install group](/concepts/app-branches#install-groups) at a time. An update can be a new release of your product, a
component upgrade, or an infrastructure change such as a new Kubernetes version.

Every install group waits on a plan approval by default, so you review the Terraform plan or Helm diff before anything
reaches a customer. You can [auto-approve plans](/concepts/workflows#workflow-approvals) on an install, or let a group
approve itself when every [policy](/concepts/policies) check passes.

To change a single customer, edit that install's [config](/guides/install-configs), or
[roll it back](/guides/rollback-install-config) to an earlier version.

## Migrations, runbooks, and debugging

For work that isn't a config change, such as a database migration or a recovery procedure,
[runbooks](/guides/runbooks) chain deploys and [actions](/concepts/actions) into one procedure you run against an
install. Actions also run on a schedule or around a deploy, and can remediate what monitoring finds.

Every run is a [workflow](/concepts/workflows) that records its steps and logs, so you can see what ran, when, and
against which install.
