## Ship to every install

- **Push to git.** A push to the tracked branch runs the [app branch](/concepts/app-branches). It builds what changed,
  then plans and deploys it one [install group](/concepts/app-branches#install-groups) at a time.
- **Review before it ships.** Each install group waits for you to approve its Terraform plan or Helm diff, or approves
  itself when every [policy](/concepts/policies) check passes.

## Change one install

- **Edit its config.** Change that install's [config](/guides/install-configs), such as its inputs or a
  [component override](/guides/component-overrides).
- **Roll back.** [Re-apply an earlier config version](/guides/rollback-install-config) on that install.

## Run migrations and day-2 work

- **[Actions](/concepts/actions)** run scripts by hand, on a schedule, or around a deploy.
- **[Runbooks](/guides/runbooks)** chain deploys and actions into one procedure, such as a database migration. Run one
  against a single install, or list it in the app branch's `post_deploy_runbooks` to run it on each install after its
  deploy.
- **[Health checks](/guides/health-checks)** show whether every component is running, with alerts to Slack and
  webhooks.

Every run is a [workflow](/concepts/workflows) that records its steps and logs, so you can see what ran, when, and
against which install.
