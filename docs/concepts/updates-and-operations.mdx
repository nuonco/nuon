## Automatic updates

Because App Templates live in git, an update is a push.

- **Roll out across installs.** A push to the tracked branch builds what changed, then plans and deploys it one
  [install group](/concepts/app-branches#install-groups) at a time.
- **Review before it ships.** Each install group waits for you to approve its Terraform plan or Helm diff.
- **Approve automatically.** [Auto-approve plans](/concepts/workflows#workflow-approvals) on an install, or let a group
  approve itself when every [policy](/concepts/policies) check passes.
- **Change one customer.** Edit that install's [config](/guides/install-configs), or
  [roll it back](/guides/rollback-install-config) to an earlier version.

## Secure execution

- **[Runner](/concepts/runners).** Each install has its own runner in the customer's cloud account. It does every
  deploy, action, and runbook there.
- **[Operation roles](/concepts/operation-roles).** The runner assumes a role scoped to each kind of work, and every
  workflow run records which role it used.
- **[Break-glass access](/concepts/operation-roles#elevated-access-and-break-glass-operations).** When a fix needs more
  access, the customer turns on an elevated role for the task, then turns it off again.

## Day-2 tooling

- **[Actions](/concepts/actions)** run scripts by hand, on a schedule, or around a deploy, and can fix what monitoring
  finds.
- **[Runbooks](/guides/runbooks)** chain deploys and actions into one procedure, such as a database migration or a
  recovery.
- **[Drift detection](/concepts/workflows#drift-detection)** finds changes made outside Nuon.

Every run is a [workflow](/concepts/workflows) that records its steps and logs, so you can see what ran, when, and
against which install.
