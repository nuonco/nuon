An Install is a running instance of an [App](/concepts/apps) in a customer's cloud account. Each install has its own infrastructure, configuration, and lifecycle. You can have many installs of the same app across different customers and environments.

## Lifecycle

When an install is created, the following are provisioned in order:

1. **Runner** - a VM in the customer's cloud that manages the install
2. **Sandbox** - the base infrastructure (networking, compute)
3. **Components** - your application (Helm charts, Terraform modules, manifests)
4. **Actions** - operational tasks (health checks, migrations)

When an install is deleted, components are removed in reverse dependency order, then the sandbox is destroyed, and the runner's stack is deleted.

## Creating an Install

Installs are typically created through the dashboard. The process involves:

1. Entering [inputs](/concepts/app-configuration#inputs) in the dashboard
2. Sharing the generated stack link (e.g., CloudFormation) with the customer
3. The customer deploys the stack in their cloud account
4. The runner starts, connects to the control plane, and provisions everything

The install progresses through a [workflow](/concepts/workflows) of steps that can be monitored, approved, and retried in the dashboard.
