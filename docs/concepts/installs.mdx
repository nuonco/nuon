## Made of

An install inherits the sandbox and components your App Template defines, and deploys the latest build of each
component. The first [workflow](/concepts/workflows), the install workflow, provisions everything in order:

## Setup

Inputs are how you tailor an install to each customer, such as API keys, cloud region, instance size, or the release
to run. Fill them in when you create the install in the dashboard, or set them in an
[install config](/guides/install-configs) when you create installs at scale.

The [stack](/concepts/stacks) can create a fresh network or build on what the customer already has, such as their VPC
or cluster. When one customer needs different Helm values or Terraform
variables, a [component override](/guides/component-overrides) changes them for that install only.

## Health and debugging

[Health checks](/guides/health-checks) show whether every component is running, with alerts to Slack and webhooks.
[Install telemetry](/concepts/install-telemetry) forwards logs, metrics, and traces to your observability backend, and
[drift detection](/concepts/workflows#drift-detection) finds changes made outside Nuon.

When a fix needs more access than the runner normally has, the customer turns on a
[break-glass role](/concepts/operation-roles#elevated-access-and-break-glass-operations) for the task, then turns it off
again.
