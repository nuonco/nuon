## Clean deprovisions

Offboard a customer and leave their data where it belongs: in their account.

When a contract ends or an install moves, your customer usually wants to keep their databases and buckets. Your
policies are there to stop exactly those resources from being deleted. Until now that meant deprovisions stalled on
your own guardrails, and cleaning up took hand-edited state and custom actions.

Mark the stateful resources a component should leave behind:

```toml components/database.toml
[teardown]
retain = [
  "aws_rds_cluster.main",
  "aws_rds_cluster_instance.main",
]
```

Nuon destroys everything else, then hands the retained resources over to your customer. The teardown plan shows
each one with a **Retain** action, so you can review exactly what stays before anything runs.
If a retained resource depends on something that would be destroyed, Nuon fails the plan instead of taking the
data with it.

Policies that protect production on every deploy can now step aside for an intentional teardown:

```toml policies.toml
[[policy]]
type              = "terraform_module"
engine            = "opa"
contents          = "./protect-rds-cluster.rego"
apply_on_teardown = false
```

Deprovisions also show up on the install's deployments page alongside every other operation, and a failed plan
step can be skipped so one stuck component no longer blocks the rest of the teardown.

Read more at [Retaining resources on teardown](/guides/retaining-resources-on-teardown) and
[Skipping policies during teardown](/concepts/policies#skipping-policies-during-teardown).

## Other updates in this release

### Scheduled runbooks

Run a [runbook](/guides/runbooks) on a cron schedule, so routine maintenance across your fleet happens without
anyone kicking it off.

```toml
[[triggers]]
type          = "cron"
cron_schedule = "0 6 * * 1"
```

### AWS cloud connections

Give Nuon access to an AWS account with short-lived OIDC credentials, so no long-lived access key is ever stored.
Create a connection once and select it when you create an install. See
[Cloud connections](/guides/cloud-connections).
