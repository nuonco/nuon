## App branches on your release cadence

Roll out when you cut a release.

- Start a run on a tag, on a merged pull request's label, or only manually, instead of on every push
- Trigger a run for a specific tag, commit, or pull request from the CLI
- Trigger runs and previews from GitHub Actions with the Nuon action

```toml branches/monthly.toml
[run]
mode       = "on_tag"
tag_prefix = "release/"
```

```sh
nuon branches trigger --branch-id main --run-type tag --run-ref v1.2.3
```

## Runner and stack control per install

Meet one customer's infrastructure requirements without changing your app for everyone.

- Keep AWS runners on a patched image: pin an approved AMI, or pick up the latest AL2023 AMI each time a runner instance launches (runner template v0.7.0+)
- Give one install its own VPC range, instance size, or other CloudFormation parameter (installs with an AWS cloud connection)

```toml runner.toml
image_auto_update = true
```

```toml installs/acme-production.toml
name             = "acme-production"
app_branch       = "main"
cloud_connection = "acme-aws"

[cloudformation.nested_stacks.VPC.parameters]
VpcCIDR = "10.42.0.0/16"

[cloudformation.nested_stacks.RunnerAutoScalingGroup.parameters]
InstanceType = "m7i.large"
```
