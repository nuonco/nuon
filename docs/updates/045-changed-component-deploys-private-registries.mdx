## Fleet view

- See every install of an app on one page, grouped by [app branch](/concepts/app-branches) and [install group](/concepts/app-branches#install-groups)
- Installs that are [unhealthy or degraded](/guides/health-checks#how-component-health-is-determined), or waiting on [approval](/concepts/workflows#workflow-approvals), are called out at the top
- Each install group shows how many installs are on the branch's latest run, or on any earlier run
- Switch to a table for each install's config version, [runner](/concepts/runners) status, and pending approvals

## More efficient customer updates

- [Components](/concepts/components) now rebuild only when their config or source changes
- Components and the [sandbox](/concepts/sandboxes) deploy only when they, or a build they [depend on](/guides/component-dependencies), differ from the last successful apply
- Each deployment lists the changed files and the commit behind it

<Tip>Edit one component's [Helm chart](/guides/helm-chart-components) template, and the next branch run deploys that component. The sandbox and every other component stay as they are.</Tip>

## Private image registries

- Pull private images from Amazon ECR, Google Artifact Registry, and Azure Container Registry with no credentials in app config
- Assign each image repository to a verified [cloud connection](/guides/cloud-connections) under **Settings > Image repositories**
- Each connection generates the setup to apply in the cloud account, as Terraform or CLI commands, plus CloudFormation on AWS

Image credentials already in app config keep working.

## Other updates in this release

### EKS access for break-glass roles

Add an [`eks_access`](/config-ref/break-glass) block to an AWS [break-glass](/concepts/break-glass) or [custom role](/concepts/operation-roles#scope-custom-operation-roles-to-a-task). The install stack grants that cluster access when the customer turns the role on and removes it when they turn it off. [CloudFormation install stacks](/guides/provision-stacks-with-cloudformation) only.

### Cloud SQL delete warnings on GCP

When a GCP [break-glass role](/concepts/break-glass#define-a-break-glass-role) holds Cloud SQL delete permissions, config validation warns if any other role can still delete, including through a predefined role such as `roles/editor` or `roles/cloudsql.admin`.

### Delete action run logs

If an [action](/concepts/actions) prints a secret, an org admin can delete that run's logs from the action run page once the run ends. Only the logs are deleted. A secret the action also wrote to an output remains in the run's outputs.
