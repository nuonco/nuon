## Deploy only what changed

Nuon now automatically reconciles your install with what has changed in your application. When a [component](/concepts/components) changes, Nuon figures out what has drifted and deploys the right components to update your install.

- Rebuild a component only when its config or source changes
- See the changed files and the commit behind each deployment

<Tip>Edit one component's [Helm chart](/guides/helm-chart-components) template, and the next branch run deploys that component. The sandbox and every other component stay as they are.</Tip>

## Private image registries

Pull private images through a [cloud connection](/guides/cloud-connections).

- Use Amazon ECR, Google Artifact Registry, or Azure Container Registry
- Assign each image repository to a cloud connection under **Settings > Image repositories**

Image credentials already in app config keep working.

## EKS access for break-glass roles

Automatically configure EKS access entries on [break-glass roles](/concepts/break-glass).

- Add an [`eks_access`](/config-ref/break-glass) block to the role
- Cluster access is granted when the customer turns the role on and removed when they turn it off

```toml break_glass.toml
[[role]]
name         = "{{.nuon.install.id}}-cluster-debug"
display_name = "Cluster debugging"
description  = "Lets the vendor debug workloads on the EKS cluster."

[[role.policies]]
name     = "eks-describe"
contents = """
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": ["eks:DescribeCluster"], "Resource": "*" }
  ]
}
"""

[role.eks_access]
cluster_name = "{{.nuon.sandbox.outputs.cluster.name}}"

[[role.eks_access.policies]]
policy_arn = "arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy"
```

Available on AWS with [CloudFormation install stacks](/guides/provision-stacks-with-cloudformation).
