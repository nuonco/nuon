The commands you'll use most. Run `nuon --help` (or `nuon <command> --help`) for the full set.

## Global flags

These work on every command.

| Flag | What it does |
|------|--------------|
| `--config <path>`, `-C <path>` | Use a custom config file instead of `~/.nuon`. Can also be set with the `NUON_CONFIG_FILE` env var. |
| `--output <format>` | Output format: `table` (default), `json`, or `agent`. Can also be set with `NUON_OUTPUT`. |
| `--read-only` | Block any command that modifies state. Can also be set with `NUON_READ_ONLY=1`. |
| `--debug` | Print per-request API timing to stderr. |

## Authenticate

| Command | What it does |
|---------|--------------|
| `nuon auth login` | Sign in (browser SSO). Run this first. |
| `nuon auth logout` | Sign out. |

## Organizations

| Command | What it does |
|---------|--------------|
| `nuon orgs select` | Switch your active org. A new trial account has a single org that's selected automatically when you log in, so you only need this once you belong to more than one. |
| `nuon orgs current` | Show the active org. |
| `nuon orgs api-tokens create --name <name>` | Create a durable API token for the current org (shown once). Requires org admin. Add `--role` (defaults to `org_read_only`; run `nuon roles list` or see [Access control](/concepts/access-control)) to set the token's permissions, or `--personal` to issue the token against your own account and its existing roles instead. |
| `nuon orgs api-tokens list` | List the current org's API tokens. |
| `nuon orgs api-tokens delete --id <token-id>` | Revoke an API token. |
| `nuon orgs update-user-role --user-id <id> --role <role>` | Change an org member's role (run `nuon roles list` or see [Access control](/concepts/access-control)). Requires org admin. |

## Apps & config

| Command | What it does |
|---------|--------------|
| `nuon apps create --name <name>` | Create an app template in the control plane. |
| `nuon apps validate [dir]` | Validate an app config directory (default: the current directory). Requires login, and it looks up the app by the directory's name, so an app with that name must exist. Run `nuon apps create` first. |
| `nuon apps list` | List your apps. |
| `nuon apps select` | Set your active app. |

## App branches

App config ships through [app branches](/guides/app-branches): a branch file points Nuon at a repository, directory,
and git branch, and a push to that git branch starts a run. Every `nuon branches` command defaults to the app you
selected with `nuon apps select` and takes `--app-id` (an app ID or name) to target another. `--branch-id` takes a
branch ID or name.

| Command | What it does |
|---------|--------------|
| `nuon branches sync --file <file-or-dir>` | Create or update app branches from branch files such as `branches/main.toml`. `--dry-run` prints the plan, `--confirm` applies it without a prompt. Passing a directory also proposes deleting config-managed branches that have no file. |
| `nuon branches list` | List the app's branches. Alias: `nuon br`. |
| `nuon branches get --branch-id <branch>` | Show a branch and its deployment groups. |
| `nuon branches trigger --branch-id <branch>` | Run the tracked git branch's latest commit. `--force` rebuilds every component, `--no-wait` returns without opening the workflow TUI. |
| `nuon branches preview` | Preview a pushed git branch (`--git-ref`) or pull request (`--pr-number`) against one install (`--install-id`). `--mode plan-only` applies nothing. With no flags it asks for each choice. |
| `nuon branches runs --branch-id <branch>` | List the branch's runs and open one in the workflow TUI. |
| `nuon branches create --name <name>` | Create a manually managed branch with no branch file. |
| `nuon branches delete --branch-id <branch> --confirm` | Delete a branch. |

<Note>
  `nuon apps sync` and `nuon sync` are deprecated. Once they are turned off for your org, running `nuon apps sync` in
  an interactive terminal offers to migrate: it writes a branch file, syncs it, and offers to move your installs onto
  the branch. See
  [Migrating from `nuon apps sync`](/guides/app-branches#migrating-from-nuon-apps-sync). `nuon apps branches` is a
  deprecated alias for `nuon branches`.
</Note>

## Installs

| Command | What it does |
|---------|--------------|
| `nuon installs create` | Create an install of the selected app. |
| `nuon installs list` | List installs. Add `--labels k=v` (repeatable) to filter; all labels must match. |
| `nuon installs get` | Show an install's details. |
| `nuon installs labels set --install-id <install> k=v ...` | Set labels on an install. Deployment group [label selectors](/guides/app-branches#selecting-installs-for-a-group) match on these. |
| `nuon installs labels list --install-id <install>` | List an install's labels. |
| `nuon installs labels unset --install-id <install> <key> ...` | Remove labels from an install. |
| `nuon installs components deploy-all` | Deploy all components to an install. |
| `nuon installs outputs` | View an install's outputs. |

## Agents / MCP

Operate Nuon from an LLM client. See [Agents](/guides/agents/overview).

| Command | What it does |
|---------|--------------|
| `nuon agents help` | Setup guide. When an agent runs it, prints orientation markdown: auth, selected org/app/install, MCP HTTP URL, and the tool catalog. |
| `nuon agents mcp` | Stdio MCP proxy (`--allow-writes` in examples so mutating tools are listed). Its URL is derived from the configured API hostname (`api.<hostname>` becomes `mcp.<hostname>/mcp`). `--url` / `--name` override the upstream server and the name in the client's MCP list. Per-client registration: [Setup](/guides/agents/setup). |
