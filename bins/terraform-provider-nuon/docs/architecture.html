nuon Terraform provider

How the nuon provider's nuon_stack resource drives the stack SDK to provision an install stack: it talks to the Nuon control plane for config, fetches and runs the Terraform module from nuonco/install-stacks, and applies resources into the customer's own cloud account (BYOC / local execution).

Example usage

terraform {
  required_providers {
    nuon = {
      source = "nuonco/nuon"
    }
  }
}

provider "nuon" {
  api_url = "https://api.nuon.co"
}

resource "nuon_stack" "example" {
  phone_home_id = var.phone_home_id

  aws {
    state_bucket = "my-nuon-tf-state"
  }

  inputs = {
    domain = "example.com"
  }

  secrets = {
    db_password = var.db_password
  }
}

Architecture

Apply host (local execution) Nuon control plane Target cloud account (BYOC) External sources

Walkthrough

  1. Bootstrap & fetch config. On terraform apply, the resource builds {api_url}/v1/stack-runs/{phone_home_id} and the SDK's FromURL POSTs a run to the Nuon control plane. ctl-api returns the rendered Config — install_id, cloud, region, the declared input/secret schema, runner IDs, log-stream credentials, and the phone-home URL. The resource overlays customer inputs/secrets onto it (unknown keys rejected; secrets write-only).
  2. Fetch the module. The SDK downloads the nuonco/install-stacks archive over HTTPS (tarball, not git clone) and extracts the cloud's subdir (aws/gcp) into an ephemeral work dir, then writes the rendered terraform.tfvars.json.
  3. Resolve the terraform binary. Either a pre-installed binary (offline / locked-down) or one downloaded via hc-install from releases.hashicorp.com.
  4. Init against remote state. The SDK writes a partial nuon_backend.tf and runs terraform init -backend-config=… pointing at the state backend in the target account (S3 or GCS, keyed nuon/<install_id>). State lives with the customer, so the work dir stays disposable and ephemeral runners just work.
  5. Apply. terraform apply (or destroy) creates the install-stack resources — VPC/subnets, IAM roles or service accounts, secret entries, and the runner compute — using the apply host's ambient cloud credentials.
  6. Stream logs. The SDK streams job output to the ctl-api log stream using the credentials minted for this run, so progress shows in the Nuon dashboard. Logs start streaming as the run begins, before the module's phone-home reports completion.
  7. Phone-home. The install-stacks module reports run status back to ctl-api directly (the SDK does not double-report for the Terraform method).
